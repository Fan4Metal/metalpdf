# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

MetalPDF is a Windows-only PDF viewer, written in Rust with egui/eframe 0.37 (glow; the `clipboard` feature is named, as it left the defaults in 0.37); the rendering is PDFium's (`pdfium.dll`, loaded at run time). Priorities: the first page on screen as the window appears, page flipping and scrolling with no blank pages, a minimal interface, few settings. `README.md` / `README.ru.md` are the user-facing docs and must be kept in sync (both languages, cross-linked, formal tone, no imperatives).

The name is written `MetalPDF` wherever people read it (UI, window title, READMEs, installer, `%APPDATA%\MetalPDF`, `%LOCALAPPDATA%\Programs\MetalPDF`, `MetalPDF_<ver>_Setup.exe`) and `metalpdf` wherever it is an identifier (Cargo package, `metalpdf.exe`, the GitHub repo `Fan4Metal/metalpdf`, the single-instance pipe).

The plan the project was started from and the lists of ideas and tasks are in `local/` (`PLAN.md`, `TODO.md`), excluded from git through `.git/info/exclude`.

## Commands

```
python tools/get_pdfium.py       # fetches the pinned pdfium.dll into vendor\pdfium (build.py and make_release.py do it)
uv run build.py                  # closes a metalpdf.exe running from target\, fetches PDFium if missing, cargo build --release
cargo build --release            # target\release\metalpdf.exe; build.rs copies pdfium.dll next to it
cargo test                       # unit tests (layout geometry, settings, FFI struct sizes, icon, i18n, update check parsing, the export's page analysis and ZIP; the thumbs crate's too: the workspace's default members)
cargo test the_sample_prints_to_pdf -- --ignored  # prints the sample on Microsoft Print to PDF into a file, as vectors and as pictures
cargo test pdfium -- --ignored --test-threads=1   # loads vendor\pdfium\pdfium.dll for real: opens, renders, reads, edits a PDF written by the test (one thread: PDFium is not thread-safe, parallel tests crash at random)
$env:METALPDF_FILES='a.pdf;b.pdf'; cargo test fonts_and_fidelity_survey -- --ignored --nocapture   # the fonts of real files, a line edited, saved, and what PDFium's writer changed (local/EDITING.md)
cargo clippy --all-targets       # must stay warning-free
python tools/notices.py          # licenses/THIRD_PARTY_NOTICES.txt from Cargo.lock (a test fails while it is stale)
python tools/make_release.py     # PDFium, tests, release build, dist\MetalPDF_<ver>_Setup.exe (Inno Setup 6) and _portable.zip
python tools/make_release.py --no-tests --install   # the same, then installs it silently over the installed copy
.\target\release\metalpdf.exe --export-icon file.ico   # the app icon for the installer; file.png gives the 256 px layer (images/icon.png)
.\target\release\metalpdf.exe --bench file.pdf         # the engine's timings for one file (DLL, open, first render, preview, text), no window
.\target\release\metalpdf.exe --export file.pdf out.docx   # saved as Word (out.pptx: PowerPoint), no window; METALPDF_EXPORT_DUMP=1 prints each page's lines with their boxes and the XY cut's groups on stderr
cargo test pdfium_the_sample_saves -- --ignored    # the sample saved as Word and PowerPoint, the archives read back
$env:METALPDF_TRACE=1; .\target\release\metalpdf.exe file.pdf   # start-up and render timings on stderr
```

The repository is a workspace: the app at the root and `thumbs/` (`metalpdf_thumbs.dll`, the Explorer thumbnail provider), both default members, so `cargo build`, `cargo test` and `cargo clippy --all-targets` cover both and the DLL lands in `target\release` beside the exe; `make_release.py` checks for it and puts it in the zip, `setup.iss` installs it (a `[Code]` step renames the old one and `pdfium.dll`, which it loads, aside: Explorer's `dllhost.exe` keeps them loaded, and a loaded DLL cannot be overwritten, only renamed; the `.old` files are deleted at the next installation and on uninstalling; `CloseApplicationsFilter=*.exe`, since Restart Manager, finding the surrogate on the DLLs and unable to close it, made a silent installation abort).

Releases: pushing a tag `vX.Y.Z` runs `.github/workflows/release.yml`, which runs `make_release.py` and publishes both files; the tag must equal the version in `Cargo.toml`. Creating or pushing a tag publishes a public release, so do it only when the user asks. `tools/setup.iss` installs per user. `.cargo/config.toml` links the CRT statically, so no VCRUNTIME140.dll is needed. These scripts mirror those of disk_flashlight, qview, qrec, metalmd and metalmpv; keep them in step (the PDFium steps are this project's own).

Trying a change: `cargo test` and `cargo clippy --all-targets`, then `uv run build.py` and run `target\release\metalpdf.exe <file>`; when the change concerns the installed copy (installer, associations, portable mode, the DLL) or the user runs the program all day, `python tools/make_release.py --no-tests --install` replaces the installed copy silently (it closes the running one first, so its settings are saved).

Toolchain: stable MSVC Rust plus VS 2022 Build Tools. In the Bash tool, `cargo` is not on PATH; prefix commands with `export PATH="$HOME/.cargo/bin:$PATH"`. A running `metalpdf.exe` locks the release binary; `build.py` closes it first (WM_CLOSE posted to its windows with a title, the visible ones, else the hidden ones (`post_close`; `taskkill` without /F skipped a minimized window), so settings are saved; killed after 3 s; `make_release.py` likewise). Heredocs containing Rust code break the Bash tool (lifetime apostrophes); write source files with the Write tool.

## PDFium

`tools/get_pdfium.py` (stdlib only) downloads the pinned `pdfium-win-x64.tgz` of bblanchon/pdfium-binaries (tag `chromium/8111`, PDFium 158.0.8111.0), checked by SHA-256, into `vendor\pdfium` (git-ignored; the release workflow downloads it every run, on Python 3.12 for tarfile's `filter`): the DLL, the headers (`include\`, the reference for `src/pdfium/sys.rs`) and the licences, which it joins into `licenses/PDFium-LICENSE.txt` (committed). pdfium-binaries keeps every release, so there is no mirror. Updating PDFium: change the tag and the SHA-256 (from the GitHub API's `digest` or a download) in the script and the same in `THIRD_PARTY_LICENSES.md`, run the script, run `cargo test pdfium -- --ignored`. PDFium is BSD-3-Clause: the installer and the archive ship `THIRD_PARTY_LICENSES.md`, `licenses\PDFium-LICENSE.txt` and `licenses\THIRD_PARTY_NOTICES.txt` (the crates' notices, `tools/notices.py`).

PDFium is **not thread-safe**: every `FPDF_*` call is made on the one engine thread (`engine.rs`); the UI thread only sees plain data (pixels, sizes, text boxes). `FPDF_RenderPageBitmap` never draws form fields, whatever the flags: every document gets a form-fill environment (`FPDFDOC_InitFormFillEnvironment`, version 1, no callbacks), `FORM_OnAfterLoadPage` after `FPDF_LoadPage` and `FPDF_FFLDraw` after each render. Progressive rendering (`FPDF_RenderPageBitmap_Start` with an `IFSDK_PAUSE`) is how a render is cancelled: PDFium asks the pause callback every hundred page objects (one large JPEG is not interruptible); `FPDF_RenderPage_Close` must follow a finished or abandoned render, and a page is closed in the order render close, `FORM_OnBeforeClosePage`, `FPDFText_ClosePage`, `FPDF_ClosePage` (`pdfium::Page::drop`). `FPDF_LCD_TEXT` is not used (colour fringes when the texture is scaled). Documents are read through `FPDF_FILEACCESS` with positional reads of a `File` opened with every sharing flag (no lock on the file; `unsigned long` positions: files of 4 GiB and more are refused). Measured (i7-13700KF): loading and initialising the DLL 2 ms, opening a small document 0.2 ms, a text page at 1700 px wide 3 ms, a page of large images 17 ms, a 200 px preview 0.3–3 ms.

## Architecture

- **`main.rs`**: arguments (`--export-icon` (`.ico`, or `.png` for the 256 px layer), `--bench <file>`, `--register`/`--unregister` (the `.pdf` association, for the installer), `--new-instance`, `--version`, `--help`, otherwise files (`normalize` mends Explorer's `C:"`); the release exe has no console, so the command line modes call `win::attach_parent_console`), the panic hook, logging (`METALPDF_TRACE`), the **engine thread started before the window** with the first file and a `FirstRender` (the page area predicted from the saved window geometry and its monitor's scale factor, else `DEFAULT_SIZE` and the system DPI, the process made DPI-aware first; the saved position's zoom, turns and page), `NativeOptions` (glow, the saved position and size, `centered` only without them; a window saved maximized is made normal and maximized by `App::new` through `MAXIMIZE_WHEN_SHOWN`, as winit shows a maximized window white before its first frame), `eframe::run_native` with `app::Startup`.
- **`app.rs`**: the eframe `App` (egui 0.37: `fn ui(&mut self, ui, frame)` with `egui::Panel::top/left/bottom(...).show(ui, ...)`, not the older `update(ctx)` / `SidePanel` API; ids are `Id::unique` (`Id::new` is deprecated), a `Ui`'s is `scope_id()`, `Atom::custom` takes an `IdSalt`, `--screenshot` goes through `ctx.request_screenshot` and its callback; egui 0.37's roomier, rounder widgets (and its darker dark buttons with brighter text) are set back to 0.36's by `style::classic_widgets` and `classic_spacing`, the family's look and the sizes the bars and the first page's predicted area were made with; the scroll style's `kinetic.rubber_band` is off, since the page area sets its offset from the anchor every frame and clamps it to a page in single-page mode), with MetalMD's model of **windows and tabs**: `App { windows: Vec<Window> }`, the root first, then the windows tabs were dragged out into (child viewports made hidden under `hidden_title`, found by it with `caption::thread_window`, cloaked, given the dark caption and the real title, shown, uncloaked after 3 frames: `Appear`, `App::appear`); `Window { tabs: Vec<Tab>, active, hwnd, outer/inner rects, page_field, … }`, `Tab { path, doc: DocState, view: ViewState, find: FindState, selection, back/forward (the jump history), editing, editor, notice }`. `App::new` sets the language, the theme, egui's options (no keyboard zoom, Windows' double-click time, `line_scroll_speed` 100: a wheel notch scrolls 100 points, not egui's 40, as every app of the family; the scroll bars a floating `ScrollStyle` 12 wide at rest and hovered alike (`floating_width` = `bar_width`), allocated their width, the handle in the text colour at 0.4 opacity, 0.85 under the mouse, no track: egui's floating bars thin out when idle and were hard to catch, `solid()`'s handle is the bar less 2 × 4 of margin, 2 points of light grey near invisible on the track, and a solid 16-point bar in the text colour was too heavy), keeps the window on a screen (`placement`), maximizes it if it was saved so (`MAXIMIZE_WHEN_SHOWN`), sets the dark caption while the window is hidden and cloaks it until it has painted 3 frames, starts the single-instance server's thread (files into `inbox`, `raise`), and makes the tabs of the files given or of the last session (the active one is already being opened by the engine under `first_id`). `logic` (runs even minimized) takes handed-over files and raises the window. `ui` every frame: `poll_engine` (the engine's events into the tabs' `DocState`/`FindState`, renders into `uploads`, `Edited` dropping the page's textures, `Saved` reopening the tab from the file saved (under another name, the tab takes that path: kept on the original, the session reopened it without the edits)), `upload_pending` (every preview and one full render a frame, the one nearest a current page first, as a `textures::Texture`), the dialogs' answers (`Ask::Open { window }`, `Ask::SaveAs { tab }`), then `window_ui` for the root and `show_viewport_immediate` for each other window (the keys of the focused one; the tab bar with the sidebar toggle (above the sidebar), Open (next to the tabs it adds to, as MetalMD), the tabs (drag along the bar, out into a window, into another window; a context menu through `ui::menu::context_menu`; a `•` on an edited tab), theme, update and About on the right; the toolbar; the find bar; the sidebar; the page area or the start page (`central`: `ui/view.rs`, a password field for an encrypted file, the error for one that failed; Ctrl+wheel over the pages is a zoom step round the pointer; the inline editor's click, commit and cancel); the drop overlay; the title `file.pdf — MetalPDF`), `close_windows`; About, the print dialog and the confirmation modal (closing a tab, a window's tabs (`Confirm::CloseTabs`: a detached window's close button, the root's while others are open, "Close others") or quitting with unsaved edits: Save as… / Discard / Cancel; Save as… closes the tab once saved) are drawn by `App::modals` **in the window in use** (`modal_window`, the focused one when the first opens, kept while any is open; drawn in the root, they were out of sight behind a detached window), so the root's commands from them go through `send_viewport_cmd_to(ViewportId::ROOT, …)`; the keys are off while any is open; the theme's caption, `--screenshot`, the engine's wanted list gathered from every window (sorted by tier; less the renders that failed, `failed_renders`, and those waiting for their upload, which were rendered again), the texture budgets (`cache::Textures::trim`), the root window's place (saved a second after it last moved, with the scale factor; its outer corner in physical pixels (`WindowGeometry::physical`; a file of 0.1.0 has points, `corner_pixels` reads both) and put back by `placement::move_to` in `App::new` before `keep_on_screen`: a position in points was turned into pixels by winit at the scale of the monitor the window was made on, so with monitors at different scales the window moved every start; verified on one monitor only), the settings when dirty (in the background, with the session and every document's position). **`consume_key` eats the key** and **lets an extra Shift (and Alt) through** (`matches_logically`): a Shift variant is checked before the plain one (Shift+F3, Shift+Space, Shift+R, Ctrl+Shift+Tab were taken by F3, Space, R, Ctrl+Tab); in `keys`, a plain-key shortcut (E, V, H, Del, Ctrl+Z) checks `typing` *before* consuming, else the text field never sees the key (Del did not work in the inline editor); Escape is consumed unconditionally, so it closes the inline editor there, not through the editor's own `key_pressed`. **Never read the context inside a `ctx.input` closure** (`ctx.pixels_per_point()` there deadlocked with the engine's `request_repaint`: egui's lock is writer-preferring, a nested read waits for the writer, which waits for the closure).
- **`single_instance.rs`** (MetalMD's): a named pipe through `interprocess`, named `metalpdf-<user>-<session>-<hash of the exe's path>` (pipe names are machine-wide: a remote desktop session and a portable copy must not take each other's files); `hand_off` writes the paths one per line and `AllowSetForegroundWindow`s the first copy (it connects with `ConnectWaitMode::Timeout`: `Stream::connect` waits on a busy pipe with `WaitNamedPipeW` forever; `main` tries the hand-off and the bind again for a second, for copies started together by Explorer, one per file); `Server::spawn` reads each connection on a thread of its own (pipe reads have no timeout). `--new-instance` (and `--screenshot`) skip it. A hand-off takes under 100 ms.
- **`search.rs`**: `FindState` (query, options, the hits by page as the engine sends them with their rectangles and the line each is on (`SearchHit::before/matched/after`, `HIT_CONTEXT` characters each side cut at line breaks by `line_before`/`line_after`), the current hit, `step` round the document, `status` "n of m+"); the find bar and the jump to the current hit (`App::find_bar`, `jump_to_hit`: once the page's text, the transform, is there) are in app.rs. A changed query or option restarts the search from the page being read, as does an edit of a page's text (`FindState::text_changed`). **The matching is the program's own** (`search::matches` over `Page::chars`, one `char` per text page index): PDFium's `FPDFText_FindStart` folds the case and bounds words in ASCII alone ("быстрый" never found "Быстрый"); the case is folded by Unicode's rules, a query's space matches a run of whitespace (a line break), whole words want no letter or digit against the match in any script.
- **`selection.rs`**: the selection as `(page, char)` pairs; `char_at` (the nearest character on the line under the point), `over_text`, `line_rects` (boxes merged line by line), `text_of` (PDFium's UTF-16 decoded, its line breaks kept; **PDFium reads a hyphen at a line's end as U+0002** in the characters' codes and as U+FFFE in `FPDFText_GetText` where it joined the word itself, often with no line break after: `selection::unhyphenate` joins the word again (the mark dropped, with a line break after it), as Acrobat copies it, and makes a mark at the text's end a `-`; copies and the search list's lines and matches go through it). `document::PageText::boxes` caches every character's box on the unrotated page. The page area starts a selection on a press over text, grows it while dragging (the scroll area is told not to scroll on a drag), clears it on a click; a double click takes the word under the pointer (`selection::word_at`: the run of letters and digits round the character, a mark alone, nothing on whitespace; with either tool, not in the editing mode; at the click's own position, since the hover position is not always there in the release frame; **a triple click counts as a double**: egui calls a click a triple when the one before the last was within twice the double-click delay, checking the distance to the last click only, so a second double click on another word within a second of the first comes as a "triple"); Ctrl+C copies `Tab::selected_text`, Ctrl+A takes the page.
- **`ui/sidebar.rs`**: Pages (thumbnails: only the visible rows laid out, each from the engine's 200 px preview at tier 5, the current one framed and scrolled to when it changes) and Outline (the bookmarks as a tree, each row drawn by hand in `outline_item`: chapters 14 pt in the strong text colour and drawn twice a pixel apart (the default font has no bold), sections 13 pt, deeper levels 12.5 pt muted; the fold's triangle in a column of its own so that a level's text lines up whether or not it has children (`OUTLINE_INDENT` 16), faint guides down the levels, 6 points above each chapter, the page number on the right (`DocState::label`), the title elided with its whole text in a tooltip, a bar behind the current bookmark (`active_item`, the last one at or before the current page), a hover background; folds closed by default, the current bookmark's opened and scrolled to when it changes; a click on the triangle, or on a row with no target, folds). The panel's width is saved when the mouse is up. Search (`SidebarTab::Search`): the hits by page in a `show_rows` list of rows drawn by hand, `SEARCH_ROW` high (a page's header low in its row, the room above parting the groups: "Page n", a rule to the edge, its hit count, a click going there; then its hits indented `SEARCH_INDENT`, each on one line elided with its whole line in a tooltip, the text before the match cut by `lead` to `SEARCH_LEAD` characters at a word so the match stays near the start, the match on `palette.search` as on the page, the current hit on a bar as the outline's current bookmark; `selectable_label` wrapped a hit over two lines whatever the job said; at most `SEARCH_ROWS`), scrolled to the current hit when it changes, a click `GoToHit`s; a search that starts opens the sidebar on it (`App::sidebar_before_search` remembers what the sidebar was, put back when the search closes).
- **Text editing** (experimental): `pdfium::Page::text_objects` (top-level text objects, invisible text (a scan's OCR layer) and clipping text left out, with bounds, text, font, the size as drawn (the object's matrix scale applied: a 1 pt font under a 24× matrix is common, and the inline editor's field, sized from the font, was all sizes before) and whether the font is an embedded subset), `set_text` (**in place first** with `FPDFText_SetText` whenever the font is not a subset or has a glyph for every character (`FPDFFont_GetGlyphPath`: a subset has the digits of a date; whitespace passes, as a space has no outline and so no path, and every edit with a space went to the stand-in before), the text then read back through a fresh text page (`object_text`) and compared loosely (`same_text`: no-break spaces, runs of whitespace), since a font that cannot encode a character drops it; a subset written by PDFium maps its space to U+00A0 and drops U+0020, so the text is tried again with no-break spaces; **a whitespace whose code PDFium picks has no width** (`FPDFFont_GetGlyphWidth` 0: PDFium takes the first code its reverse lookup of the ToUnicode map finds, and a Piter book's PetersburgC maps both its space, code 30, and code 32, no glyph, width 0, to U+0020: the edited words ran together) makes the text go through `FPDFText_SetCharcodes` with the codes `Page::char_codes` finds by trying 0–255 in scratch objects (the advance from the box between two inked codes, the character from the text page; 3 ms), the stand-in when a character has none; still wrong, the old text is put back and the stand-in takes over: a new object with the old one's matrix, colour, render mode and, for a stroked mode, stroke colour and width in a **stand-in font** from `fonts.rs`: the fonts installed on Windows (`%WINDIR%\Fonts` and the user's `%LOCALAPPDATA%\Microsoft\Windows\Fonts`, `.ttf` only: PDFium embeds TrueType outlines) are indexed once by their name tables (`read_names`: the table directory and the `name` table alone, Windows Unicode English strings preferred; family, subfamily, full and PostScript names), and `find` looks the base font name up by PostScript name (a PDF's base font name usually is one: `ArialNarrow-Bold`, `Roboto-Bold`; the subset tag off, `PS`/`MT`/`PSMT` tails off, the standard 14 turned into Arial, Times New Roman, Courier New), then by full name, then by family in the wanted weight and slant, then by family; failing all, `style_of` reads bold, italic, serif and monospaced off the name and the descriptor flags (fixed pitch, italic, force bold; the serif flag is not trusted) and `file_of` picks Arial, Times New Roman or Courier New in that weight and slant; `Fonts` keeps the bytes (`pdfium::FontLookup`, a closure `set_text` calls with the name and the flags; before this, plain Arial stood in and bold runs came back regular), and the stand-in font is loaded into the document once (`DocumentInner::stand_ins`, closed with it: loaded for every edit, each load was a font of its own in the file, and one no run used any more was saved whole, 1.1 MB for three edits), and the new object's matrix is scaled horizontally so the run keeps the old run's width a character (`FPDFPageObj_GetBounds` before and after; a same-length edit fills the same box); `FPDFPage_GenerateContent`; the text page reloaded), `Document::save_to` (`FPDF_SaveAsCopy`, `NO_INCREMENTAL | SUBSET_NEW_FONTS`, through a temporary file; the `FPDF_FILEWRITE` is the first field of a `#[repr(C)]` writer, which the callback casts back). Pictures: `Page::image_objects` (top-level image objects with bounds), `remove_object`, `replace_image` (a JPEG through `FPDFImageObj_LoadJpegFileInline` over the file's bytes in memory, a PNG decoded with the `png` crate to a BGRA `Bitmap::from_bgra` and `FPDFImageObj_SetBitmap`; then `FPDFImageObj_SetMatrix` fits the picture into the old box with its own proportions, centred), `place_object` (three `FPDFPageObj_Transform`s: to the origin, scaled, to the new box). The engine applies edits (`engine::Edit`: `Text { objects, text, followers }` through `Page::set_line` (the objects of a line made one, the first, with the text, by `set_text`'s rules (`replace_text`, the content not regenerated; a stand-in fits its width a character to all the objects merged); the others removed; the followers moved along the line's direction by the change in the ink's reach, the last glyph's edge before and the new object's after; the first set first, so a failure leaves the page as it was), `Remove`, `ReplaceImage`, `Place`; objects named by their index at the time, the log replayed in order so the indices stay right) to a second copy of the file (`EditState`: opened at the first edit, from the file only if it has not changed on disk since it was opened (`open_source`, the length and time of change kept at `Open`: the edits name objects of the pages shown); the files edits read (a picture, another PDF) copied into `%TEMP%\metalpdf-edits-<pid>` first (`keep_files`, `edit_files`, removed with the tab), so a replay finds them when the originals are gone; `edit_obstacles` are kept and checked against each edit by `refuse`: a signed or encrypted document takes none; **a page whose content `FPDFPage_GenerateContent` cannot write back whole takes none**: PDFium's generator leaves out text in Type 3 fonts (Chrome and Edge print variable fonts, Cascadia among them, as Type 3: the code spans of a printed web page vanished on saving), shadings (`sh`) and inline images; `Page::has_type3_text` (a font with no bytes, `FPDFFont_GetFontData`) is checked before the edit, and `Page::content_changed`, after every regeneration, parses the page again from the new content (`FPDF_LoadPage` anew) and compares the object counts by type, refusing the edit when any are missing, **and compares the look** (`boxes_apart`: the page in memory and the parsed one rendered at 72 dpi, `check_render`, in 8 × 8 boxes by mean colour, a box 32 levels apart in a channel refusing the edit), on which the engine rebuilds the copy from the log (`rebuild_edits`, which keeps the copy when the file cannot be opened again); the writer puts a fill colour in the stream only when it is DeviceRGB (CMYK black, grey and a Separation, the Piter book's PANTONE headings, came out black), so `colours_to_rgb` sets every object's fill and stroke colour again as the RGB PDFium reports before the content is written, between two renders that catch an object whose reported colour is not what it draws (a coloured tiling pattern reads as grey 0xBFBFBF: the shields.io badges of README.ru.pdf), a soft mask is dropped, and fonts are told apart by base name alone (two subsets `BAAAAA+PTSans-Bold` of a LibreOffice page were written as one, the other's letters blank: `Page::clashing_fonts` refuses before the edit when two embedded fonts of one name differ in size; a pair not embedded is left to the look check); the writer also leaves out `Tc`/`Tw` while keeping the `TJ` kerning, so a run set with them parsed with its characters closer or further by the spacing each (the Piter book's 8 pt lines by 4.5 pt at their ends), which the look check lets through: `undo_drift` measures it on the parsed page (`char_origins`: the characters' origins by object through the text page, the made-up ones left out), shifts the runs' positions in memory the other way (`FPDFText_SetPositions`, relative to the run's origin in text space) and writes the content once more, which then parses to where the characters were (the writer is linear in the positions: one pass, 6e-5 pt left); note that `FPDFPage_GenerateContent` writes nothing when no object is dirty, so a spike that regenerates without an edit measures nothing (`colours_to_rgb` dirties every object on the real path); **the parsed page then takes the place of the one in memory** (`Page::handle` is a `Cell`), so what is shown after an edit is what a save writes; `generate_content_drops_type3_text`, `grey_and_spot_colours_survive_a_save`, `two_fonts_of_one_name_are_told_apart` and `character_spacing_survives_an_edit` document the behaviour on hand-written pages, and `fonts_and_fidelity_survey` (`METALPDF_FILES=a.pdf;b.pdf`, `--nocapture`; `local/EDITING.md` has the findings) lists the fonts of real files, edits a line, saves and measures what the writer changed; a tagged one takes every edit: `FPDFPage_GenerateContent` writes the marked content back (measured on the OpenStax book: every MCID kept, saved and read back), and a stand-in run takes the old object's marks (`Page::copy_marks`: names, numbers, strings; a name value becomes a string) and its index (`FPDFPage_InsertObjectAtIndex`), so the content's order and the other objects' indices stay; refusing tagged documents had rested on the belief that the marks were dropped), renders and reads edited pages from it, rebuilds it from the log on undo (`rebuild_edits` is all or nothing: a log that does not replay whole puts the copy back as it was, an undo that fails puts its edit back in the log; - **`engine.rs`**: the engine thread and its scheduler. The UI replaces the list of wanted renders wholesale each frame (`Engine::want`, `(RenderKey, tier)` in order: tier 0 a preview of a visible page that has no texture at all, 1 the full renders of the visible pages from the centre out, 3 previews of the neighbours, 4 full renders of 2 pages ahead and 1 behind), and sends `Request`s (open, close, size batches of 128 with the page labels, outline, text layout, links, search) which the thread serves first. A render is progressive: the pause callback fires when the list changed (an `AtomicU64` generation), the thread then drops a render nobody wants any more, or makes a tier-0 preview on another page handle in the pause (`preview_pixels`, on the cached page or one loaded for it) and continues; `want` compares the tiers too, so a preview that became urgent moves the generation. Results come back as `Event`s through a channel with `request_repaint`; a key sent and not yet polled is left out of the next list (`done`). Full renders carry their mip levels (`pixels::Pixels`, a 2×2 box filter on the thread) and give a 200 px preview for free (`Kind::Preview`, from the level at most that wide). A page whose whole render would pass `TILE_PIXELS` (16 MP) or the GPU's texture side (`too_large`) is never rendered whole: the UI asks for **tiles** (`Kind::Tile { x, y, w, h }`, a rectangle in pixels of the page at the key's width; rendered with the page placed at `-x, -y` on a bitmap of the tile's size, mip levels like a full render, no free preview); the first render before the window is skipped for such a page. The worker skips a key already in `done` when it picks the next render (the list the UI sent while a render ran names that render too, which rendered every key twice), and `want` clears `busy` when the new list no longer names the render under way, which `still_wanted` then drops at its next pause. ## Conventions

- Every user-visible string goes through `tr!("English", "Русский")` (`i18n.rs`); the language follows the Windows UI language (`i18n::system_lang`, `GetUserDefaultUILanguage`) unless chosen in About (`i18n::LangChoice`, `system`/`en`/`ru` in the settings; applied in `App::new` before any text is made and at once when changed). Strings are built every frame, so nothing caches translated text. Log messages, CLI output and technical errors stay English.
- Persisted state (`settings.rs`, JSON): `theme` (`system`/`light`/`dark`), `language`, `check_updates`, `last_update_check` (Unix seconds), `recent`, `positions`, `session`, `session_active`, `window`, `view_mode` (`continuous`/`single`), `zoom` (`fitwidth`/`fitpage`/`{"scale": z}`), `sidebar_visible`, `sidebar_width`, `sidebar_tab` (`thumbnails`/`outline`/`search`), `sidebar_side` (`left`/`right`), `dark_style` (`grey`/`black`), `tool` (`select`/`hand`), `find_case`, `find_words`, `print` (`printer`, `scale` `shrink`/`fit`/`actual`/`custom`, `percent`, `auto_rotate`, `as_image`); a position carries `page_shift`.
- The version comes from `Cargo.toml` (`main::VERSION`, shown in About). Between releases it is the next version with `-dev`, the last number raised by one (after `0.1.0`, `0.1.1-dev`), and `build.rs` appends `git describe --tags --always --match v[0-9]*` (`0.1.1-dev (v0.1.0-2-g4bd494d)`); a release version is shown as is. Release: drop `-dev`, commit `Version X.Y.Z`, tag `vX.Y.Z` (release.yml checks the tag against `Cargo.toml`), then set the next `-dev` version (`X.Y.(Z+1)-dev`).
- The release profile has `panic = "abort"` and no console: a panic shows a message box (`main::install_panic_hook`) and ends the program. `f32::clamp` panics when its bounds cross; sizes read from files may be 0.
- Commits in this repository end with the trailer `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` (as in disk_flashlight and metalmd); this overrides the global "no Co-Authored-By" rule for this repo only. Commit when a change is done and checked (tests, build), unrelated changes in separate commits; push only when the user asks.
- `cargo fmt` is not run on this project (long lines are allowed, as in qview); `cargo clippy --all-targets` must stay clean.
- GUI checks: the OpenGL client area cannot be captured with `PrintWindow` on an NVIDIA machine (the caption can, from a DPI-aware process); keys can be posted with `PostMessage(WM_KEYDOWN/WM_KEYUP)`. A launched window takes the focus: warn the user before launching test windows and before any simulated global mouse or keyboard input, and close test windows with `taskkill /PID` (WM_CLOSE, which saves the settings).
