## Установка

Установщик и портативный архив публикуются на странице [Releases](https://github.com/Fan4Metal/metalpdf/releases).

Установщик `MetalPDF_<версия>_Setup.exe` не требует прав администратора: программа помещается в `%LOCALAPPDATA%\Programs\MetalPDF`. Установленная программа хранит настройки в `%APPDATA%\MetalPDF`.

Портативный архив `MetalPDF_<версия>_portable.zip` содержит программу в папке `MetalPDF` и работает без установки. В нём также лежит пустой файл `app.ron`: пока он находится рядом с `metalpdf.exe` и папка доступна для записи, настройки хранятся в нём, так что программу можно носить на съёмном диске. Без этого файла настройки хранятся в `%APPDATA%\MetalPDF`, как у установленной программы. Окно «О программе» показывает, где хранятся настройки.

Исполняемые файлы не подписаны, поэтому при первом запуске Windows SmartScreen может предупредить о неизвестном издателе.

## Проверка обновлений и конфиденциальность

Проверка обновлений необязательна и по умолчанию выключена. Если в окне «О программе» включён флажок **Проверять обновления при запуске (раз в сутки)**, программа не чаще раза в сутки запрашивает у GitHub Releases API (`api.github.com`) последний выпуск; кнопка **Проверить сейчас** в том же окне делает запрос немедленно. Запрос не содержит ничего, кроме версии программы в заголовке `User-Agent`; ничего не скачивается и не устанавливается: если есть более новый выпуск, рядом с кнопкой «О программе» появляется кнопка с его версией, открывающая страницу выпуска в браузере. В остальном программа к сети не обращается.

## Сборка

Требования: Windows 10 или новее, стабильный Rust (цель MSVC, редакция 2024) и Visual Studio 2022 Build Tools с компонентами C++. Для `build.py` нужен [uv](https://docs.astral.sh/uv/).

```
uv run build.py          # target\release\metalpdf.exe
cargo test
```

`build.py` сначала закрывает `metalpdf.exe`, запущенный из папки `target` проекта (иначе файл заблокирован), затем выполняет `cargo build --release`. Если программа не запущена, достаточно обычного `cargo build --release`. Исполняемый файл линкует среду выполнения C статически (`.cargo/config.toml`), поэтому ничего, кроме самой Windows, ему не нужно.

## Установщик и выпуск

Скрипт выпуска собирает исполняемый файл, установщик и портативный архив. Для него нужен [Inno Setup 6](https://jrsoftware.org/isinfo.php).

```
python tools/make_release.py              # тесты, release-сборка, установщик, архив
python tools/make_release.py --no-tests   # то же без cargo test
python tools/make_release.py --install    # затем тихая установка поверх установленной копии
```

Скрипт записывает файлы в `dist`, версия берётся из `Cargo.toml`. Скрипт установщика — `tools/setup.iss`; значок установщика записывает `metalpdf.exe --export-icon <файл.ico>`.

Выпуски на GitHub собирает рабочий процесс **Release** (`.github/workflows/release.yml`). После обновления версии в `Cargo.toml` и коммита отправка соответствующего тега публикует выпуск с установщиком и портативным архивом:

```
git tag v0.1.0
git push origin v0.1.0
```

Рабочий процесс останавливается, если тег не совпадает с версией в `Cargo.toml`. Ручной запуск (Actions → Release → Run workflow) собирает файлы и прикрепляет их к запуску, не создавая выпуск.
