# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

MetalPDF is a Windows-only PDF viewer, written in Rust with egui/eframe 0.36 (glow); the rendering is PDFium's (`pdfium.dll`, loaded at run time). Priorities: the first page on screen as the window appears, page flipping and scrolling with no blank pages, a minimal interface, few settings. `README.md` / `README.ru.md` are the user-facing docs and must be kept in sync (both languages, cross-linked, formal tone, no imperatives).

The name is written `MetalPDF` wherever people read it (UI, window title, READMEs, installer, `%APPDATA%\MetalPDF`, `%LOCALAPPDATA%\Programs\MetalPDF`, `MetalPDF_<ver>_Setup.exe`) and `metalpdf` wherever it is an identifier (Cargo package, `metalpdf.exe`, the GitHub repo `Fan4Metal/metalpdf`, the single-instance pipe).

The plan the project was started from and the lists of ideas and tasks are in `local/` (`PLAN.md`, `TODO.md`), excluded from git through `.git/info/exclude`.

## Commands

```
python tools/get_pdfium.py       # fetches the pinned pdfium.dll into vendor\pdfium (build.py and make_release.py do it)
uv run build.py                  # closes a metalpdf.exe running from target\, fetches PDFium if missing, cargo build --release
cargo build --release            # target\release\metalpdf.exe; build.rs copies pdfium.dll next to it
cargo test                       # unit tests (layout geometry, settings, FFI struct sizes, icon, i18n, update check parsing)
cargo test pdfium -- --ignored --test-threads=1   # loads vendor\pdfium\pdfium.dll for real: opens, renders, reads, edits a PDF written by the test (one thread: PDFium is not thread-safe, parallel tests crash at random)
cargo clippy --all-targets       # must stay warning-free
python tools/notices.py          # licenses/THIRD_PARTY_NOTICES.txt from Cargo.lock (a test fails while it is stale)
python tools/make_release.py     # PDFium, tests, release build, dist\MetalPDF_<ver>_Setup.exe (Inno Setup 6) and _portable.zip
python tools/make_release.py --no-tests --install   # the same, then installs it silently over the installed copy
.\target\release\metalpdf.exe --export-icon file.ico   # the app icon for the installer; file.png gives the 256 px layer (images/icon.png)
.\target\release\metalpdf.exe --bench file.pdf         # the engine's timings for one file (DLL, open, first render, preview, text), no window
$env:METALPDF_TRACE=1; .\target\release\metalpdf.exe file.pdf   # start-up and render timings on stderr
```

Releases: pushing a tag `vX.Y.Z` runs `.github/workflows/release.yml`, which runs `make_release.py` and publishes both files; the tag must equal the version in `Cargo.toml`. Creating or pushing a tag publishes a public release, so do it only when the user asks. `tools/setup.iss` installs per user. `.cargo/config.toml` links the CRT statically, so no VCRUNTIME140.dll is needed. These scripts mirror those of disk_flashlight, qview, qrec, metalmd and metalmpv; keep them in step (the PDFium steps are this project's own).

Trying a change: `cargo test` and `cargo clippy --all-targets`, then `uv run build.py` and run `target\release\metalpdf.exe <file>`; when the change concerns the installed copy (installer, associations, portable mode, the DLL) or the user runs the program all day, `python tools/make_release.py --no-tests --install` replaces the installed copy silently (it closes the running one first, so its settings are saved).

Toolchain: stable MSVC Rust plus VS 2022 Build Tools. In the Bash tool, `cargo` is not on PATH; prefix commands with `export PATH="$HOME/.cargo/bin:$PATH"`. A running `metalpdf.exe` locks the release binary; `build.py` closes it first (WM_CLOSE posted to its windows with a title, the visible ones, else the hidden ones (`post_close`; `taskkill` without /F skipped a minimized window), so settings are saved; killed after 3 s; `make_release.py` likewise). Heredocs containing Rust code break the Bash tool (lifetime apostrophes); write source files with the Write tool.

## PDFium

`tools/get_pdfium.py` (stdlib only) downloads the pinned `pdfium-win-x64.tgz` of bblanchon/pdfium-binaries (tag `chromium/8111`, PDFium 158.0.8111.0), checked by SHA-256, into `vendor\pdfium` (git-ignored, cached in CI by the script's hash): the DLL, the headers (`include\`, the reference for `src/pdfium/sys.rs`) and the licences, which it joins into `licenses/PDFium-LICENSE.txt` (committed). pdfium-binaries keeps every release, so there is no mirror. Updating PDFium: change the tag and the SHA-256 (from the GitHub API's `digest` or a download) in the script and the same in `THIRD_PARTY_LICENSES.md`, run the script, run `cargo test pdfium -- --ignored`. PDFium is BSD-3-Clause: the installer and the archive ship `THIRD_PARTY_LICENSES.md`, `licenses\PDFium-LICENSE.txt` and `licenses\THIRD_PARTY_NOTICES.txt` (the crates' notices, `tools/notices.py`).

PDFium is **not thread-safe**: every `FPDF_*` call is made on the one engine thread (`engine.rs`); the UI thread only sees plain data (pixels, sizes, text boxes). `FPDF_RenderPageBitmap` never draws form fields, whatever the flags: every document gets a form-fill environment (`FPDFDOC_InitFormFillEnvironment`, version 1, no callbacks), `FORM_OnAfterLoadPage` after `FPDF_LoadPage` and `FPDF_FFLDraw` after each render. Progressive rendering (`FPDF_RenderPageBitmap_Start` with an `IFSDK_PAUSE`) is how a render is cancelled: PDFium asks the pause callback every hundred page objects (one large JPEG is not interruptible); `FPDF_RenderPage_Close` must follow a finished or abandoned render, and a page is closed in the order render close, `FORM_OnBeforeClosePage`, `FPDFText_ClosePage`, `FPDF_ClosePage` (`pdfium::Page::drop`). `FPDF_LCD_TEXT` is not used (colour fringes when the texture is scaled). Documents are read through `FPDF_FILEACCESS` with positional reads of a `File` opened with every sharing flag (no lock on the file; `unsigned long` positions: files of 4 GiB and more are refused). Measured (i7-13700KF): loading and initialising the DLL 2 ms, opening a small document 0.2 ms, a text page at 1700 px wide 3 ms, a page of large images 17 ms, a 200 px preview 0.3–3 ms.

## Architecture

- **`main.rs`**: arguments (`--export-icon` (`.ico`, or `.png` for the 256 px layer), `--bench <file>`, `--register`/`--unregister` (the `.pdf` association, for the installer), `--new-instance`, `--version`, `--help`, otherwise files (`normalize` mends Explorer's `C:"`); the release exe has no console, so the command line modes call `win::attach_parent_console`), the panic hook, logging (`METALPDF_TRACE`), the **engine thread started before the window** with the first file and a `FirstRender` (the page area predicted from the saved window geometry and its monitor's scale factor, else `DEFAULT_SIZE` and the system DPI, the process made DPI-aware first; the saved position's zoom, turns and page), `NativeOptions` (glow, the saved position and size, `centered` only without them; a window saved maximized is made normal and maximized by `App::new` through `MAXIMIZE_WHEN_SHOWN`, as winit shows a maximized window white before its first frame), `eframe::run_native` with `app::Startup`.
- **`app.rs`**: the eframe `App` (egui 0.36: `fn ui(&mut self, ui, frame)` with `egui::Panel::top/left/bottom(...).show(ui, ...)`, not the older `update(ctx)` / `SidePanel` API), with MetalMD's model of **windows and tabs**: `App { windows: Vec<Window> }`, the root first, then the windows tabs were dragged out into (child viewports made hidden under `hidden_title`, found by it with `caption::thread_window`, cloaked, given the dark caption and the real title, shown, uncloaked after 3 frames: `Appear`, `App::appear`); `Window { tabs: Vec<Tab>, active, hwnd, outer/inner rects, page_field, … }`, `Tab { path, doc: DocState, view: ViewState, find: FindState, selection, back/forward (the jump history), editing, editor, notice }`. `App::new` sets the language, the theme, egui's options (no keyboard zoom, Windows' double-click time, `line_scroll_speed` 100: a wheel notch scrolls 100 points, not egui's 40, as every app of the family; the scroll bars a floating `ScrollStyle` 12 wide at rest and hovered alike (`floating_width` = `bar_width`), allocated their width, the handle in the text colour at 0.4 opacity, 0.85 under the mouse, no track: egui's floating bars thin out when idle and were hard to catch, `solid()`'s handle is the bar less 2 × 4 of margin, 2 points of light grey near invisible on the track, and a solid 16-point bar in the text colour was too heavy), keeps the window on a screen (`placement`), maximizes it if it was saved so (`MAXIMIZE_WHEN_SHOWN`), sets the dark caption while the window is hidden and cloaks it until it has painted 3 frames, starts the single-instance server's thread (files into `inbox`, `raise`), and makes the tabs of the files given or of the last session (the active one is already being opened by the engine under `first_id`). `logic` (runs even minimized) takes handed-over files and raises the window. `ui` every frame: `poll_engine` (the engine's events into the tabs' `DocState`/`FindState`, renders into `uploads`, `Edited` dropping the page's textures, `Saved` reopening a tab saved over its file), `upload_pending` (every preview and one full render a frame, the one nearest a current page first, as a `textures::Texture`), the dialogs' answers (`Ask::Open { window }`, `Ask::SaveAs { tab }`), then `window_ui` for the root and `show_viewport_immediate` for each other window (the keys of the focused one; the tab bar with Open, the sidebar toggle, the tabs (drag along the bar, out into a window, into another window; a context menu through `ui::menu::context_menu`; a `•` on an edited tab), theme, update and About on the right; the toolbar; the find bar; the sidebar; the page area or the start page (`central`: `ui/view.rs`, a password field for an encrypted file, the error for one that failed; Ctrl+wheel over the pages is a zoom step round the pointer; the inline editor's click, commit and cancel); the drop overlay; the title `file.pdf — MetalPDF`), `close_windows`, About, the confirmation modal (closing a tab or quitting with unsaved edits: Save as… / Discard / Cancel), the theme's caption, `--screenshot`, the engine's wanted list gathered from every window (sorted by tier), the texture budgets (`cache::Textures::trim`), the root window's place (saved a second after it last moved, with the scale factor), the settings when dirty (in the background, with the session and every document's position). **`consume_key` eats the key**: in `keys`, a plain-key shortcut (E, V, H, Del, Ctrl+Z) checks `typing` *before* consuming, else the text field never sees the key (Del did not work in the inline editor); Escape is consumed unconditionally, so it closes the inline editor there, not through the editor's own `key_pressed`. **Never read the context inside a `ctx.input` closure** (`ctx.pixels_per_point()` there deadlocked with the engine's `request_repaint`: egui's lock is writer-preferring, a nested read waits for the writer, which waits for the closure).
- **`single_instance.rs`** (MetalMD's): a named pipe through `interprocess`, named `metalpdf-<user>-<session>-<hash of the exe's path>` (pipe names are machine-wide: a remote desktop session and a portable copy must not take each other's files); `hand_off` writes the paths one per line and `AllowSetForegroundWindow`s the first copy; `Server::spawn` reads each connection on a thread of its own (pipe reads have no timeout). `--new-instance` (and `--screenshot`) skip it. A hand-off takes under 100 ms.
- **`search.rs`**: `FindState` (query, options, the hits by page as the engine sends them with their rectangles and the line each is on (`SearchHit::before/matched/after`, `HIT_CONTEXT` characters each side cut at line breaks by `line_before`/`line_after`), the current hit, `step` round the document, `status` "n of m+"); the find bar and the jump to the current hit (`App::find_bar`, `jump_to_hit`: once the page's text, the transform, is there) are in app.rs. A changed query or option restarts the search from the page being read.
- **`selection.rs`**: the selection as `(page, char)` pairs; `char_at` (the nearest character on the line under the point), `over_text`, `line_rects` (boxes merged line by line), `text_of` (PDFium's UTF-16 decoded, its line breaks kept). `document::PageText::boxes` caches every character's box on the unrotated page. The page area starts a selection on a press over text, grows it while dragging (the scroll area is told not to scroll on a drag), clears it on a click; a double click takes the word under the pointer (`selection::word_at`: the run of letters and digits round the character, a mark alone, nothing on whitespace; with either tool, not in the editing mode; at the click's own position, since the hover position is not always there in the release frame; **a triple click counts as a double**: egui calls a click a triple when the one before the last was within twice the double-click delay, checking the distance to the last click only, so a second double click on another word within a second of the first comes as a "triple"); Ctrl+C copies `Tab::selected_text`, Ctrl+A takes the page.
- **`ui/sidebar.rs`**: Pages (thumbnails: only the visible rows laid out, each from the engine's 200 px preview at tier 5, the current one framed and scrolled to when it changes) and Outline (the bookmarks as a tree of `CollapsingState`s, `active_item` the last one at or before the current page, opened and scrolled to when it changes). The panel's width is saved when the mouse is up. Search (`SidebarTab::Search`): the hits by page in a `show_rows` list (a page header, then its hits as selectable labels with the match in the accent colour, at most `SEARCH_ROWS`), scrolled to the current hit when it changes, a click `GoToHit`s; a search that starts opens the sidebar on it (`App::sidebar_before_search` remembers what the sidebar was, put back when the search closes).
- **Text editing** (experimental): `pdfium::Page::text_objects` (top-level text objects with bounds, text, font, the size as drawn (the object's matrix scale applied: a 1 pt font under a 24× matrix is common, and the inline editor's field, sized from the font, was all sizes before) and whether the font is an embedded subset), `set_text` (**in place first** with `FPDFText_SetText` whenever the font is not a subset or has a glyph for every character (`FPDFFont_GetGlyphPath`: a subset has the digits of a date), the text then read back through a fresh text page (`object_text`) and compared loosely (`same_text`: no-break spaces, runs of whitespace), since a font that cannot encode a character drops it; a subset written by PDFium maps its space to U+00A0 and drops U+0020, so the text is tried again with no-break spaces; still wrong, the old text is put back and the stand-in takes over: a new object with the old one's matrix, colour and render mode in a **stand-in font** from `fonts.rs`: the fonts installed on Windows (`%WINDIR%\Fonts` and the user's `%LOCALAPPDATA%\Microsoft\Windows\Fonts`, `.ttf` only: PDFium embeds TrueType outlines) are indexed once by their name tables (`read_names`: the table directory and the `name` table alone, Windows Unicode English strings preferred; family, subfamily, full and PostScript names), and `find` looks the base font name up by PostScript name (a PDF's base font name usually is one: `ArialNarrow-Bold`, `Roboto-Bold`; the subset tag off, `PS`/`MT`/`PSMT` tails off, the standard 14 turned into Arial, Times New Roman, Courier New), then by full name, then by family in the wanted weight and slant, then by family; failing all, `style_of` reads bold, italic, serif and monospaced off the name and the descriptor flags (fixed pitch, italic, force bold; the serif flag is not trusted) and `file_of` picks Arial, Times New Roman or Courier New in that weight and slant; `Fonts` keeps the bytes (`pdfium::FontLookup`, a closure `set_text` calls with the name and the flags; before this, plain Arial stood in and bold runs came back regular), and the new object's matrix is scaled horizontally so the run keeps the old run's width a character (`FPDFPageObj_GetBounds` before and after; a same-length edit fills the same box); `FPDFPage_GenerateContent`; the text page reloaded), `Document::save_to` (`FPDF_SaveAsCopy`, `NO_INCREMENTAL | SUBSET_NEW_FONTS`, through a temporary file; the `FPDF_FILEWRITE` is the first field of a `#[repr(C)]` writer, which the callback casts back). Pictures: `Page::image_objects` (top-level image objects with bounds), `remove_object`, `replace_image` (a JPEG through `FPDFImageObj_LoadJpegFileInline` over the file's bytes in memory, a PNG decoded with the `png` crate to a BGRA `Bitmap::from_bgra` and `FPDFImageObj_SetBitmap`; then `FPDFImageObj_SetMatrix` fits the picture into the old box with its own proportions, centred), `place_object` (three `FPDFPageObj_Transform`s: to the origin, scaled, to the new box). The engine applies edits (`engine::Edit`: `Text`, `Remove`, `ReplaceImage`, `Place`; objects named by their index at the time, the log replayed in order so the indices stay right) to a second copy of the file (`EditState`: opened at the first edit; `edit_obstacles` are kept and checked against each edit by `refuse`: a signed or encrypted document takes none, a tagged one only the page operations, which leave the content streams alone, not the content edits, since `FPDFPage_GenerateContent` drops the marked content the tags point into; OpenStax's books are tagged, and refusing them page operations looked like a broken menu), renders and reads edited pages from it, rebuilds it from the log on undo, saves it; `Request::Objects/Edit/UndoEdit/Save`, `Event::Objects/Edited/EditFailed/Saved`; after `Edited` the UI drops the page's textures, objects, selection and editor (the indices may have changed). The UI: `E` or the pencil outlines the text runs and the pictures; a run under the pointer shows a tooltip with its font and size as drawn and, for a subset, the installed font that would stand in (`TextObject::stand_in`, the engine fills it through `Fonts::stand_in_name` when it sends the objects) or that the font is not installed and which generic family would (`fonts::generic_name`); a click on a run opens an `InlineEditor` (an egui text field over the object, scaled with the page), Enter commits; a click on a picture selects it (`ImageSel`: moved by dragging, resized by its corner handles keeping the proportions, in unrotated page points mapped back to page space through `PageText::rect_to_page_space`; Replace… asks for a JPEG or PNG, `Ask::ReplaceImage`; Delete or `Del` removes it); Ctrl+Z undoes, Ctrl+S is always Save As (the original replaced only when chosen; saved over, the tab is reopened from the new file). Pages: `Document::delete_page`, `insert_blank_page` (`FPDFPage_New`), `import_pages` (`FPDF_ImportPagesByIndex` with no indices: every page of the source); `Edit::InsertBlank/InsertPdf/ReplacePdf/DeletePage` (a replacement imports after the page and deletes it, one log entry; the last page is never deleted). Such an edit **restructures** the document: every open page handle is dropped, every page comes from the edited copy from then on (`EditState::all_pages`, `Worker::view_doc` for sizes, labels, the outline, renders and the search), and `Event::Restructured { page_count }` makes the UI drop the document's textures and read the sizes and the rest again (`DocState::restructure`), the view's page clamped. The operations are in the thumbnails' context menu (`ui/sidebar.rs`: insert a blank page or a PDF's pages before or after, replace with a PDF's pages, delete; `Ask::ImportPdf`). `cargo test pdfium -- --ignored --test-threads=1` edits and saves the sample (a run's text; the picture on page 2 placed, replaced by a PNG written by the test, removed; a page deleted, a blank one put in, another sample's pages imported); with `METALPDF_SAMPLE=<file>` it edits a real document's first runs and compares the ink in their boxes.
- **`ui/licenses.rs`** (MetalMPV's): About → Licenses…: MetalPDF's MIT, PDFium's licences (`licenses/PDFium-LICENSE.txt`, written by `tools/get_pdfium.py` from the archive) and the crates' notices (`tools/notices.py`); a test fails while the notices are older than Cargo.lock.
- **`engine.rs`**: the engine thread and its scheduler. The UI replaces the list of wanted renders wholesale each frame (`Engine::want`, `(RenderKey, tier)` in order: tier 0 a preview of a visible page that has no texture at all, 1 the full renders of the visible pages from the centre out, 3 previews of the neighbours, 4 full renders of 2 pages ahead and 1 behind), and sends `Request`s (open, close, size batches of 128 with the page labels, outline, text layout, links, search) which the thread serves first. A render is progressive: the pause callback fires when the list changed (an `AtomicU64` generation), the thread then drops a render nobody wants any more, or makes a tier-0 preview on another page handle in the pause and continues. Results come back as `Event`s through a channel with `request_repaint`; a key sent and not yet polled is left out of the next list (`done`). Full renders carry their mip levels (`pixels::Pixels`, a 2×2 box filter on the thread) and give a 200 px preview for free (`Kind::Preview`, from the level at most that wide). A page whose whole render would pass `TILE_PIXELS` (16 MP) or the GPU's texture side (`too_large`) is never rendered whole: the UI asks for **tiles** (`Kind::Tile { x, y, w, h }`, a rectangle in pixels of the page at the key's width; rendered with the page placed at `-x, -y` on a bitmap of the tile's size, mip levels like a full render, no free preview); the first render before the window is skipped for such a page. The worker skips a key already in `done` when it picks the next render (the list the UI sent while a render ran names that render too, which rendered every key twice), and `want` clears `busy` when the new list no longer names the render under way, which `still_wanted` then drops at its next pause. Open pages (`FPDF_PAGE` + text page) are kept in a small LRU (`PAGE_CACHE`): loading parses the content and keeps the decoded images. `FirstRender` makes the first file's first render before the window exists, at the width `layout::render_width` gives, the same sum the UI does in its first frame.
- **`document.rs`**: `DocState`, the UI's copy of a document: status (`Loading`, `Ready`, `NeedsPassword`, `Failed`), page count, sizes (asked in batches, the batch round a page jumped to first, `need_sizes_near`), labels, the outline, the text layouts (`PageText` with the page-to-view affine, `rect_to_page`) and links of the pages asked for, each asked once.
- **`cache.rs`**: `Textures`: two LRU pools under byte budgets (full renders ~400 MB with mips, previews 24 MB), keyed by `RenderKey`; nothing used in the frame just drawn is evicted; `nearest` gives another render of the page (a larger one first, full renders only) while the exact one is on its way; `tiles_of` lists the tiles of a page at a width. Tiles live in the full pool.
- **`textures.rs`**: qview's glow upload (`BGRA` / `UNSIGNED_INT_8_8_8_8_REV`, the levels from the engine, no `glGenerateMipmap`; `TEXTURE_SWIZZLE_A = ONE` since BGRx's fourth byte is whatever PDFium left), deleted deferred (`delete_dropped` at the start of a frame). Measured: a 1626 × 2300 page with 13 levels uploads in 5–9 ms once the driver's pool is warm, 20–30 ms the first time. **The mip chain rounds down** (`pixels.rs`: level n is `max(1, size >> n)`): built with `div_ceil`, level sizes differed from what OpenGL expects, the textures were incomplete and every page sampled black (found with `--screenshot`; the plain screen captures had been black for the usual NVIDIA reason, which hid it). A render that comes back black is a mipmap chain to check first.
- **`--screenshot FILE.png`** (`App::screenshot`): egui's `ViewportCommand::Screenshot` reads the framebuffer at frame 60 and the program ends; the README's picture is made so (`metalpdf.exe --screenshot images\screenshot.png file.pdf`, with the sidebar and the window size set in the settings first), as the OpenGL area cannot be captured from outside on an NVIDIA machine.
- **`view.rs`**: `ViewState`: mode, zoom, turns, the `layout::Anchor`, the horizontal offset, the view's size, `settle_until` (new full renders wait 120 ms after a zoom step or a resize; the renders at hand are drawn scaled meanwhile), `forward` (the prefetch direction); `set_zoom` keeps the document point under the pointer where it is, `page_step` is a screen less 24 points (single-page mode: the next page once the bottom is reached), `go_to_point` for links.
- **`ui/view.rs`**: the pages in an `egui::ScrollArea` whose offset is set from the anchor each frame and read back after (the wheel, the bar), each page from the exact texture, else the nearest render scaled, else the preview, else white paper, snapped to physical pixels; a page too large to render whole (`engine::too_large`) is drawn from **tiles**: the nearest full render or the preview underneath, then every tile at hand that touches the view, then the tile that holds the part in view, which is the one at hand that contains it, else the one the tab waits for (`Tab::tiles`, so the key stays put while it renders), else a new one: the part in view plus `TILE_MARGIN` of the view's size on every side, its edges on a `TILE_GRID` of page pixels, clamped to the page; no full render is prefetched for such a page. Measured at 800 % on the OpenStax book: a 3328 × 3328 tile renders in 12–16 ms (debug build) and uploads in 60–100 ms; at 3200 % a 4096 × 3072 tile in 9 ms; the wanted list; **the wheel is read from the raw events** (`wheel_notches`: `Event::MouseWheel` in notches, `Line` as is, `Point` over `WHEEL_STEP`, a pinch through `ViewState::pinch_notches`), not from `zoom_delta`/`smooth_scroll_delta`, since egui smooths a notch over several frames and a step a frame made Ctrl+wheel zoom four steps a notch; Ctrl+wheel goes to `ViewState::zoom_wheel` (a step per whole notch, the remainder kept, dropped when the wheel turns back), and in single-page mode the scroll area is not given the wheel (`ScrollSource::SCROLL_BAR`): `ViewState::wheel_single` scrolls a page taller than the view by `WHEEL_STEP` a notch and at its edge, or on a page that fits, turns a page per whole notch; links (hovered outlined, the pointer a hand, a click reported); the **context menu** (`ui::menu::context_menu` on the area's response; what the right button was over is noted in `Tab::menu`, a `MenuContext`, when it is let go, since the pointer then moves onto the menu: the editing mode's text run or picture, the link, whether there is a selection; the items come back in `ViewOutput`: copy, select all, copy a link's address, open it, copy the picture (in any mode: the page objects are asked for every visible page, not only in the editing mode; `Request::ImagePixels` → `Page::image_pixels`: `FPDFImageObj_GetRenderedBitmap` renders a point as a pixel, the size the picture has on the page, so the object's matrix is scaled to the image's own pixel size (`FPDFImageObj_GetImagePixelSize`, at most 8192 a side) for the render and put back after, masks and transparency applied; BGRA/BGRx/BGR/grey turned into RGBA → `Event::ImagePixels` → `ctx.copy_image`, egui-winit's arboard with `image-data`), edit the run, replace or delete the picture (editing mode), the tool, the editing mode); the **tool** (`settings::Tool`, `V`/`H`): the hand gives the scroll area `ScrollSource::DRAG` and senses clicks only on the page area (egui registers its drag-to-scroll *before* the content, so a drag sense on the area, registered later, takes every drag and the hand moves nothing), starts no selection and leaves the pointer an arrow; its icon is `Move`, four arrows; the text tool senses drags and makes the selection; the editing mode's drags are its own whatever the tool; `page_point_to_screen` / `screen_to_page_point` for the turns.
- **`ui/toolbar.rs`**: the toolbar under the tab bar (a top panel; there is no status bar): the page field (a label or a number, Enter goes there; Ctrl+G focuses it), the count, zoom −/+ and a menu (fit width, fit page, 50–800 %), the three presets as lit toggles (`FitWidth`, `FitPage`, `ActualSize`), turns, continuous/single, the tool toggles (`SelectText`, `Hand`), the pencil, a note on the right (a notice, "Edited, not saved"; truncated, whole in its tooltip). **Page numbering**: the right button on the page field offers to read the numbers printed on the pages (`Request::DetectNumbering` → `engine::numbering_shift` over two dozen sampled pages' first and last 200 characters, the shift most agree on, `Event::Numbering`; 51 ms on the OpenStax book, shift 16), to state the number of the page shown (`ThisPageIs`), or the file's own (`FileNumbering`); `DocState::page_shift` makes `label` show printed numbers, the field's `resolve` reads typed numbers as printed ones (the file's outside that range), and the shift is kept in the document's `FilePosition`. A zoom chosen by name (a preset, the menu, Ctrl+0/1/2) is remembered as `settings.zoom`, the zoom new documents open at (`App::remember_zoom`); the steps are not.
- **`ui/home.rs`**: the start page (icon, name, version, the hint or the engine's error, the recent files, "Clear recent"), as MetalMD's.
- **`assoc.rs`**: the `.pdf` association under HKCU (ProgID `MetalPDF.pdf` with the app icon, `OpenWithProgids`, `Applications\metalpdf.exe`, `Capabilities` in `RegisteredApplications`); never `UserChoice`. Tested in a scratch key.
- **`dialog.rs`** (MetalMPV's): the file dialogs on a thread of their own, the window as their owner, the answer taken in the next frames. **`placement.rs`** (MetalMD's): `keep_on_screen`, `show_maximized`, `bring_to_front`. **`style.rs`**: `Palette` (backdrop, page edge and shadow, link, search and selection highlights, error) per theme.
- **`pdfium/sys.rs`**: the PDFium C API declared by hand (fpdfview.h, fpdf_progressive.h, fpdf_formfill.h, fpdf_text.h, fpdf_doc.h, fpdf_edit.h, fpdf_save.h): `LoadLibraryExW` of `pdfium.dll` next to the exe (a debug build also tries `vendor\pdfium`), `GetProcAddress` per function into `struct Api` (a macro), `LoadError` (`NotFound`, `Unusable`). The exe has no import of the DLL: without it the program starts and says what is missing. Struct layouts are tested (x64 sizes).
- **`pdfium/mod.rs`**: the safe layer, engine thread only: `init` (once per process, never destroyed), `Document::open` (file access, form environment, `OpenError` from `FPDF_GetLastError`: `Password` makes the UI ask for one), page count and sizes (`FPDF_GetPageSizeByIndexF`, /Rotate applied, without loading the content), `page_label`, `meta_text`, `outline` (bookmarks as a tree, budgeted against cycles), `Page`: `render` (plain), `render_start`/`render_continue`/`render_close` (progressive, with a `Pause` closure and an optional `ColorScheme`), `text_layout` (every character's code, loose box and origin in page space), `text`, `find`, `text_rects`, `links` (GoTo and URI), `page_to_view` (the affine from page space to the page as shown, derived from `FPDF_PageToDevice` on a fine grid: /Rotate and the CropBox offset, so text boxes and links land on the pixels), `Bitmap` (BGRx over a `Box<[u8]>` that must not move while PDFium holds it). The tests write a two-page PDF by hand (`tests::sample_pdf`: Helvetica text, a /Rotate 90 page with a link, bookmarks) and check rendering, the progressive path against the plain one pixel for pixel, text, search, links, bookmarks.
- **`bench.rs`**: `--bench`: timings of the engine for one file, the first page to a PNG in `%TEMP%`.
- **`layout.rs`**: pure page geometry, tested: `Layout::new` places every page one under another, centred in a document as wide as the widest page, in both modes, so that the scroll bar spans the document in single-page mode too; there `visible`/`current` give the one page the view's top is on, `page_scroll_range` the offsets that show it alone (its top with the gap to its bottom with the gap at the view's bottom; a page that fits has one position) and `clamp_scroll` keeps an offset within a page (the page area clamps the anchor's offset to its page each frame; a drag of the bar out of the page lands on another page, `anchor_at`, and the next frame clamps into that one: dragging the bar turns pages; `ViewState::scroll_by` and `at_edge` use the page's range, not the document's) at a scale from `ZoomSetting` (`FitWidth` to the widest known page, so the zoom does not drift while scrolling; `FitPage`; `Scale`, 1.0 = 100 % = a PDF point as 96/72 of a view point, Acrobat's count), with unknown page sizes taking the first page's; the scroll position is an `Anchor` (page, share of its height), so page sizes arriving late above it and zoom changes leave the view where it is; `visible`, `current`, `zoom_step` along a ladder (`ZOOM_STEPS`), `pixel_width` (the integer width renders are keyed by).
- **`icon.rs`** draws the app icon (a white sheet with a folded corner and grey text lines, a red "PDF" label across its lower part; layers of 24 px and less drop the letters and the lines) with no dependencies; `build.rs` includes it via `#[path]` to write the `.ico` embedded by `winresource` and `app_icon_{64,128,256}.rgba` into `OUT_DIR` (drawn again only when the icon's sources change: a stamp with their hash); `main::embedded_icon` and `ui::app_icon` use those, so nothing is rasterised at start-up. `build.rs` also copies `vendor\pdfium\pdfium.dll` into `target\<profile>`.
- **`settings.rs`**: JSON through serde (`%APPDATA%\MetalPDF\config\settings.json`, or `metalpdf.json` next to the exe when that file exists and can be written: portable mode, `settings::location`, decided once per run; the portable zip ships it empty; About shows which): theme, language, update check, recent files (9), per-file positions (page, offset, zoom, rotation; 100), the session's tabs, the window's geometry with the monitor's scale factor, view mode, zoom, sidebar, find options. `#[serde(default)]`, a `.tmp` + rename write, numbered background saves (the last one asked for wins); a test reads the file of version 0.1.0 with defaults for later fields.
- **`update.rs`**: the opt-in update check (off by default, once a day at start-up, "Check now" in About): `win::https_get` (WinHTTP) asks `api.github.com/repos/…/releases/latest`, `tag_name` is picked out of the JSON by hand, a newer release shows `ui::update_button` beside About, opening the release page built from `CARGO_PKG_REPOSITORY`. `cargo test update -- --ignored` asks GitHub for real.
- **`caption.rs`**: `DWMWA_USE_IMMERSIVE_DARK_MODE` for the caption, `WM_NCACTIVATE` off and on to repaint it (Windows 10 repaints it only on the next non-client repaint), `cloak` (`DWMWA_CLOAK`), `thread_window` (a child viewport's window by its title).
- **`win.rs`**: `error_box` (user32 `MessageBoxW` declared by hand), `attach_parent_console`, `shell_open` (`ShellExecuteW`; eframe's `links` feature is off), `https_get`, `wide`.
- **`ui/`**: `app_icon`, toolbar buttons with a painted icon (`icon_button`), `theme_button` (as in Windows → light → dark), `about_button`, `update_button`, `close_cross`; `ui/about.rs` the About modal.
- **`ui/icons.rs`**: the painted icons shared by the family (the default fonts lack many symbols), on a 14-point grid with 1.3-point lines. A new icon is added there on the same grid and checked next to the others with `cargo run --example icons`, not drawn ad hoc in a panel. This project added `Continuous`, `SinglePage`, `Sidebar`, `FitWidth`, `FitPage` and `ActualSize` (also put into the skill's catalogue, `templates/src/ui/icons.rs`).

## Conventions

- Every user-visible string goes through `tr!("English", "Русский")` (`i18n.rs`); the language follows the Windows UI language (`i18n::system_lang`, `GetUserDefaultUILanguage`) unless chosen in About (`i18n::LangChoice`, `system`/`en`/`ru` in the settings; applied in `App::new` before any text is made and at once when changed). Strings are built every frame, so nothing caches translated text. Log messages, CLI output and technical errors stay English.
- Persisted state (`settings.rs`, JSON): `theme` (`system`/`light`/`dark`), `language`, `check_updates`, `last_update_check` (Unix seconds), `recent`, `positions`, `session`, `session_active`, `window`, `view_mode` (`continuous`/`single`), `zoom` (`fitwidth`/`fitpage`/`{"scale": z}`), `sidebar_visible`, `sidebar_width`, `sidebar_tab` (`thumbnails`/`outline`/`search`), `tool` (`select`/`hand`), `find_case`, `find_words`; a position carries `page_shift`.
- The version comes from `Cargo.toml` (`main::VERSION`, shown in About). Between releases it is the next version with `-dev`, the last number raised by one (after `0.1.0`, `0.1.1-dev`), and `build.rs` appends `git describe --tags --always --match v[0-9]*` (`0.1.1-dev (v0.1.0-2-g4bd494d)`); a release version is shown as is. Release: drop `-dev`, commit `Version X.Y.Z`, tag `vX.Y.Z` (release.yml checks the tag against `Cargo.toml`), then set the next `-dev` version (`X.Y.(Z+1)-dev`).
- The release profile has `panic = "abort"` and no console: a panic shows a message box (`main::install_panic_hook`) and ends the program. `f32::clamp` panics when its bounds cross; sizes read from files may be 0.
- Commits in this repository end with the trailer `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` (as in disk_flashlight and metalmd); this overrides the global "no Co-Authored-By" rule for this repo only. Commit when a change is done and checked (tests, build), unrelated changes in separate commits; push only when the user asks.
- `cargo fmt` is not run on this project (long lines are allowed, as in qview); `cargo clippy --all-targets` must stay clean.
- GUI checks: the OpenGL client area cannot be captured with `PrintWindow` on an NVIDIA machine (the caption can, from a DPI-aware process); keys can be posted with `PostMessage(WM_KEYDOWN/WM_KEYUP)`. A launched window takes the focus: warn the user before launching test windows and before any simulated global mouse or keyboard input, and close test windows with `taskkill /PID` (WM_CLOSE, which saves the settings).
